# Avito: отбор до 50 объявлений услуг

Основное решение получило **Recall@50 = 0.897443** на платформе. Оно использует
лексический и семантический поиск, историю взаимодействий, географию,
дообученный query-encoder E5 и LightGBM LambdaRank.

## Что открывать и отправлять

| Файл или папка | Назначение |
| --- | --- |
| **Avito.ipynb** | Единственный основной notebook. Restart Kernel → Run All создаёт answer.csv. |
| **answer.csv** | Ответ лучшего подтверждённого решения, для загрузки на платформу. |
| **docs/SOLUTION.md** | Данные, признаки, обучение, проверка качества, ошибки и ограничения. |
| **experiments/Avito_neural_experiments.ipynb** | Отчёты и явный запуск обучения и экспериментов через RUN_*; по умолчанию обучение выключено. |
| **archive/** | Старые notebooks, ответы, документация и архивы версий. |
| **models/** | Необходимые локальные модели, включая исходную E5 и исторические компоненты. |
| **artifacts/** | Обученные модели, векторы, кэши и отчёты. Это зависимости текущего решения и следующих экспериментов. |
| **.development/** | Комментированные вспомогательные скрипты обучения, проверки и упаковки. |
| **deliverables/avito_solution.zip** | Архив основного решения с локальными весами для проверяющего. |

## Воспроизведение

1. Распаковать `deliverables/avito_solution.zip` в отдельную папку.
2. Положить в неё исходные `train.parquet`, `benchmark_queries.parquet` и
   `benchmark_items.parquet`; установить зависимости из `requirements.txt`.
3. Открыть `Avito.ipynb` и выполнить Restart Kernel → Run All.
4. Полученный `answer.csv` должен побайтово совпасть с отправленным ответом.

Обычный запуск использует сохранённые веса и векторы, без повторного обучения.
Он работает на CPU или GPU без внешних inference API. Модели и данные проверяются
по SHA-256. Большие веса не хранятся в GitHub: для локального воспроизведения
проверяющему нужен архив с весами. Исходные Parquet в архив не включены.

## Как работаем дальше

Следующий кандидат v8 разрабатывается в ветке `feature/ranker-v8`.
Отчёт: [docs/EXPERIMENTS_V8.md](docs/EXPERIMENTS_V8.md).
Его отдельный ответ — `experiments/results/v8/answer.csv`, notebook —
`experiments/Avito_v8_candidate.ipynb`, комплект для воспроизведения —
`deliverables/avito_v8_solution.zip`. Метрика v8 на платформе пока неизвестна;
корневые notebook и CSV остаются подтверждённой версией v7.

Основной notebook и ответ представляют подтверждённую лучшую версию. Новые
эксперименты запускаем через notebook в `experiments/`, сравниваем на том же
development, записываем результаты и только после проверки переносим улучшение
в основное решение. Прежнюю версию сохраняем в Git и архиве.

Полная рецептура нового encoder и ранкера:
`.development/export_query_encoder_candidate.py`; OOF-обучение и сравнение:
`.development/query_encoder_rank.py`. Исторические notebooks в `archive/notebooks/`
сохранены для анализа и рецептур прежних компонентов; они не являются текущими
точками запуска. Старые генераторы и упаковщики в `.development/` относятся
к историческим версиям и не предназначены для обновления основного notebook.

Текущие служебные команды, из корня проекта:

```text
python .development/validate_current.py
python .development/package_current.py
python .development/verify_current.py
```

Для проверки без установленного окружения эти команды используют имеющиеся
локальные папки зависимостей, если они присутствуют. `verify_current.py` запускает
notebook в свежей распаковке на CPU с отключённой сетью и удалённым исходным CSV.
