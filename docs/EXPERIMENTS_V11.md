# Эксперименты v11

Решение ищет до 50 объявлений на каждый запрос в корпусе из 189 212 услуг.
Основная метрика — Recall@50, усреднённый по запросам. Лучший **подтверждённый
платформой** результат до этих экспериментов: v10, **0.911829**. Локальные
значения ниже относятся к валидации и не являются оценкой платформы.

## Данные и протокол

Использованы `train.parquet`, `benchmark_queries.parquet` и
`benchmark_items.parquet`. Кандидатный пул, признаки и границы train/validation
унаследованы от v10; разметка benchmark неизвестна и не используется. В
валидации отдельно считаются новые тексты и известные тексты с новым
контекстом. Для исторических признаков исключаются собственные пары; при
обучении используются только запросы, для которых положительное объявление
присутствует в фиксированном корпусе. При оценке используется полный пул
кандидатов, а не подвыборка отрицательных примеров. Полнота пула в локальной
валидации составляет около 0.995; ошибки за его пределами ранкер исправить
не может.

Базовый каскад v10 включает лексический поиск, локальные векторы E5 и
BGE-M3, обученный query encoder, историю взаимодействий и LightGBM ranker.
`search_category` уже входит в базовые признаки; значение 0 означает
отсутствие ограничения. Жёсткое отсечение по категории отдельно проверено и
не изменило локальный Recall@50, поэтому не добавлено. Внешние API при
обучении и применении не вызываются.

## Новые сигналы

Вычислены относительные признаки BGE-M3: положение оценки объявления среди
всех 189 212 объявлений, отступ от первого и пятидесятого места и нормировка
по 512 лучшим оценкам. Справочник рассчитан для текстов запросов и текстов с
фильтрами на одном и том же корпусе при обучении и применении. Этот блок
сам по себе не улучшил локальную оценку и в выбранную модель не включён.

Отдельно добавлены структурные признаки: совпадение явного вида и типа услуги
с параметрами объявления; частота локации и сочетания подкатегории с
локацией в корпусе; признаки дистанционной работы и выезда; взаимодействие
выезда с расстоянием. Отсутствие значения кодируется как пропуск, а
несовпадение не отсекает кандидата. Такие поля нужны, потому что короткий
текст запроса не всегда передаёт ограничения, выставленные через фильтры.
Для 14 438 обучающих положительных пар с известным видом услуги точное
совпадение составляло 97.59%; для 6 897 пар с известным типом — 81.63%.
Оставшиеся исключения показывают, почему жёсткая фильтрация опасна.

Третье направление — трудные кандидаты. Три LightGBM-модели обучаются на
двух третях обучающих групп, разделённых по **тексту запроса**, и оценивают
оставшуюся треть. Для каждой группы сохраняются все положительные объявления,
до 400 наиболее высоко оценённых прочих кандидатов и до 96 случайных из
остатка. Затем на полученной выборке обучается итоговый ранкер. Прочие
кандидаты считаются отрицательными только в рамках наблюдаемого лога:
отсутствие клика не доказывает нерелевантность.

Код экспериментов: `.development/bge_reference_v11.py`,
`.development/rank_features_v11.py`, `.development/quality_v11.py`.
Применение финальной модели: `.development/quality_model_v11.py`.

## Локальная проверка

Повторный расчёт v10 в том же коде даёт matched Recall@50 **0.959901**
(unseen **0.954191**, held **0.955074**). Это сопоставимая база для таблицы;
ранее сохранённый отчёт v10 показывает 0.959726, разница +0.000175. Причина
небольшого расхождения пока не установлена, поэтому сравниваются только
оценки, повторно вычисленные вместе с новыми моделями.

| Вариант | Matched Recall@50 | Unseen macro | Held macro |
| --- | ---: | ---: | ---: |
| v10, повторный расчёт | 0.959901 | 0.954191 | 0.955074 |
| Относительные BGE-признаки, отдельный ранкер | 0.958403 | 0.953162 | 0.953309 |
| Относительные BGE-признаки, 50% RRF с v10 | 0.960789 | 0.955221 | 0.955662 |
| Структурные признаки, отдельный ранкер | 0.960359 | 0.957721 | 0.956838 |
| Структурные признаки, 50% RRF с v10 | **0.961181** | 0.956838 | 0.957426 |
| Трудные примеры, отдельный ранкер | 0.959130 | 0.955515 | 0.956397 |
| Трудные примеры, 50% RRF с v10 | 0.960576 | 0.955515 | 0.955809 |
| Трудные примеры + структурные признаки, отдельный ранкер | 0.959602 | 0.957574 | 0.957279 |
| Трудные примеры + структурные признаки, 50% RRF с v10 | 0.960897 | 0.957426 | 0.957279 |

Из шести заранее заданных смесей максимум дал четырёхмодельный RRF:
**0.961235**. Он выше простой смеси структурного ранкера с v10 на 0.000053,
то есть менее чем на одно попадание в локальном наборе. Для финального
кандидата выбран более простой и лучше проверяемый вариант с весами 50/50.

На ранее использованном контрольном срезе blend 50% понизил Recall@50 с
0.958333 до 0.956667: ноль улучшенных и один ухудшенный запрос из 600.
Контроль не использовался для выбора веса. Малые различия и нестабильность
контроля требуют проверки на платформе перед заменой лучшего отправленного
ответа.

## Ошибки и ограничения

- Примерно 0.5% локальных положительных объявлений отсутствуют в широком
  кандидатном пуле. Перестановка его объявлений не решает эти пропуски; в этом
  эксперименте генераторы пула не изменялись.
- Для коротких и неоднозначных запросов текстовая близость может спутать
  разные виды или типы услуг. Явные параметры добавлены как мягкие признаки;
  неполное соответствие разметке не позволяет фильтровать по ним жёстко.
- Совпадение локации само по себе недостаточно для выездных или дистанционных
  услуг. Добавлены признаки типа работы и взаимодействия с расстоянием.
- Верхние позиции обучающего пула содержат похожие объявления без
  наблюдаемого выбора. Их усиление через text-held hard mining немного помогло
  в смеси, но не превзошло простой структурный вариант. Эти объявления не
  считаются доказанно нерелевантными.
- Контрольный срез неоднократно использовался в предыдущих версиях, поэтому
  он не является новым независимым тестом. Его ухудшение на одном запросе и
  слабая связь локального Recall с платформой ограничивают уверенность в
  переносе прироста. Только отправка может измерить скрытую метрику.

## Выбранный ответ и воспроизведение

Финальный LightGBM обучен на 39 672 522 парах из 52 943 контекстных групп.
Используются 104 признака: 94 базовых v10 и 10 структурных. На каждом
запросе ранги этого ранкера и финального v10 объединяются по RRF с весами
50/50. Полные оценки хранятся до выбора top-50; ограничение до 50
применяется только в конце. На benchmark ответы v10 и v11 в среднем имеют
47.79 общих объявления из 50, то есть изменение консервативное.

Ответ: `experiments/results/v11/answer.csv`.
SHA-256: `8ce7401347beb1806f962ae1e72999fa93c89201b1044cd2433494f50e837d7e`.
В файле ровно 2 452 уникальных `query_id`, две колонки без индекса и не более
50 уникальных валидных `item_id` на строку. Идентификаторы сверены с исходными
Parquet-файлами. Платформенная оценка v11 пока неизвестна.

Для повторения достаточно распаковать `deliverables/avito_v11_solution.zip`,
положить туда три исходных Parquet-файла, установить `requirements.txt` и
выполнить `Avito.ipynb` целиком. Он применяет локальные веса и проверяет
SHA-256 созданного `answer.csv`. Первый запуск в рабочей папке выполнялся на
CPU с отключённой сетью. Отдельная проверка из свежей распаковки фиксируется
в `artifacts/bge-m3-v11/reproduction.json`.

## Используемые библиотеки и модели

Локальные open-source библиотеки: pandas, NumPy, scikit-learn, LightGBM,
SciPy, PyArrow, joblib, PyTorch, Transformers, Sentence Transformers, FAISS.
Локальные модели E5, BGE-M3 и compact cross-encoder входят в базовый v10
каскад; их точные файлы и версии зафиксированы в поставляемом архиве и
`docs/EXPERIMENTS_V10.md`. Данные train используются только локально.
